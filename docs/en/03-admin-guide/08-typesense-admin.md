# Typesense Web Administration UI

## Введение

Полнофункциональный веб-интерфейс для управления Typesense через панель администратора PayloadCMS. Все функции доступны без использования CLI или прямого API доступа.

## Навигация

Все функции Typesense Admin доступны через раздел "Typesense Admin" в боковом меню:

- **Коллекции** (`/admin/typesense/collections`) - Управление коллекциями
- **API Ключи** (`/admin/typesense/api-keys`) - Управление API ключами
- **Scoped Keys** (`/admin/typesense/scoped-keys`) - Генерация ограниченных ключей
- **Синонимы** (`/admin/typesense/synonyms`) - Управление синонимами
- **Overrides** (`/admin/typesense/overrides`) - Курация результатов поиска
- **Aliases** (`/admin/typesense/aliases`) - Управление алиасами для zero-downtime реиндексации
- **Cluster Health** (`/admin/typesense/cluster`) - Мониторинг здоровья кластера
- **Analytics** (`/admin/typesense/analytics`) - Аналитика поиска

## Управление коллекциями

### Просмотр коллекций

На странице `/admin/typesense/collections` отображаются все Typesense коллекции с:
- Количеством документов
- Количеством полей
- Статусом здоровья (healthy/warning/error)
- Датой создания

### Удаление коллекций

1. Нажмите кнопку "Delete" на карточке коллекции
2. Подтвердите удаление
3. Коллекция и все её документы будут удалены

**Внимание:** Удаление коллекции необратимо!

### Просмотр схемы

Нажмите "Details" на карточке коллекции для просмотра полной схемы коллекции в формате JSON.

## Управление документами

### Просмотр документов

1. Перейдите в коллекцию и нажмите "View Documents"
2. Или откройте `/admin/typesense/documents/[collection]`

### Создание документа

1. Нажмите "+ Add Document"
2. Заполните обязательное поле `id`
3. Добавьте данные в формате JSON
4. Нажмите "Create Document"

### Редактирование документа

1. Нажмите на документ в таблице для раскрытия
2. Нажмите "Edit"
3. Измените данные в JSON редакторе
4. Нажмите "Update Document"

### Импорт документов

1. Нажмите "Import"
2. Загрузите JSON файл или вставьте JSON массив
3. Все документы должны иметь поле `id`
4. Нажмите "Import Documents"

Формат JSON:
```json
[
  {"id": "1", "title": "Document 1", "content": "..."},
  {"id": "2", "title": "Document 2", "content": "..."}
]
```

### Удаление документов

- **Одиночное удаление:** Раскройте документ и нажмите "Delete"
- **Массовое удаление:** Выберите документы чекбоксами и нажмите "Delete Selected"

## Управление API ключами

### Создание API ключа

1. Перейдите в `/admin/typesense/api-keys`
2. Нажмите "+ Create API Key"
3. Введите метку (label) для идентификации
4. Установите срок действия (опционально)
5. Нажмите "Create API Key"
6. **Скопируйте ключ сразу** - он больше не будет показан!

### Просмотр ключей

В таблице отображаются:
- Метка ключа
- Тенант
- Дата создания
- Срок действия
- Последнее использование
- Количество использований

### Отзыв ключа

1. Найдите ключ в таблице
2. Нажмите "Revoke"
3. Подтвердите отзыв

## Scoped Search Keys

### Генерация ключа

1. Перейдите в `/admin/typesense/scoped-keys`
2. Нажмите "+ Generate Key"
3. Выберите коллекцию
4. Добавьте фильтры через визуальный конструктор:
   - Выберите поле
   - Выберите оператор (equals, contains, etc.)
   - Введите значение
5. Установите срок действия (в секундах)
6. Нажмите "Generate Key"
7. Скопируйте ключ - он содержит встроенные фильтры и не может быть изменен клиентом

### Использование

Scoped ключи автоматически применяют фильтры при каждом запросе, обеспечивая изоляцию данных на уровне ключа.

## Управление синонимами

### Создание синонимов

1. Выберите коллекцию на `/admin/typesense/synonyms`
2. Нажмите "+ Create Synonym"
3. Введите ID синонима
4. Выберите тип:
   - **Multi-way:** Все термины эквивалентны (bidirectional)
   - **One-way:** Корневой термин расширяется до синонимов
5. Добавьте синонимы (минимум 1 для multi-way, минимум 2 для one-way)
6. Для one-way укажите корневой термин (или используйте первый синоним)
7. Установите локаль (опционально)
8. Нажмите "Create Synonym"

### Примеры

**Multi-way:**
```
Synonyms: ["blazer", "coat", "jacket"]
```
Все три термина взаимозаменяемы.

**One-way:**
```
Root: "smart phone"
Synonyms: ["iphone", "android"]
```
Запрос "smart phone" найдет документы с "iphone" или "android", но не наоборот.

### Тестирование

Используйте кнопку "Test" для проверки влияния синонимов на результаты поиска.

## Управление Overrides (Курация)

### Создание override

1. Выберите коллекцию на `/admin/typesense/overrides`
2. Нажмите "+ Create Override"
3. Введите ID override
4. Настройте правило:
   - **Query:** Текст запроса для сопоставления
   - **Filter By:** Фильтр для динамического сопоставления
   - **Match Type:** exact, contains, или wildcard
5. Настройте действия:
   - **Pinned Documents:** Документы для показа в топе (с позицией)
   - **Excluded Documents:** Документы для скрытия
   - **Sort By:** Динамическая сортировка
   - **Filter By:** Дополнительный фильтр
6. Нажмите "Create Override"

### Примеры

**Пин документа:**
```
Query: "best seller"
Pinned: [{id: "123", position: 1}]
```

**Исключение документа:**
```
Query: "sale"
Excluded: [{id: "456"}]
```

**Динамическая сортировка:**
```
Filter By: "store:={store}"
Sort By: "sales.{store}:desc"
```

## Управление Aliases

### Создание алиаса

Aliases используются для zero-downtime реиндексации:

1. Перейдите в `/admin/typesense/aliases`
2. Создайте алиас, указывающий на текущую коллекцию
3. Создайте новую коллекцию с обновленной схемой
4. Реиндексируйте данные в новую коллекцию
5. Обновите алиас, чтобы он указывал на новую коллекцию (атомарная операция)
6. Удалите старую коллекцию после проверки

### Zero-Downtime процесс

1. **Создать алиас** → указывает на `collection_v1`
2. **Создать новую коллекцию** → `collection_v2`
3. **Реиндексировать** → скопировать все документы
4. **Валидировать** → проверить данные
5. **Обновить алиас** → атомарно переключить на `collection_v2`
6. **Очистить** → удалить `collection_v1`

## Конфигурация поиска

### Настройка параметров

1. Откройте `/admin/typesense/search-config/[collection]`
2. Настройте параметры:
   - **Default Query By:** Поля для поиска по умолчанию
   - **Default Sorting Field:** Поле сортировки по умолчанию
   - **Typo Tolerance:** Уровень толерантности к опечаткам
   - **Prefix/Infix Search:** Настройки префиксного и инфиксного поиска
   - **Tokenization:** Символы для индексации и разделители токенов

**Примечание:** Некоторые настройки требуют пересоздания коллекции.

## Мониторинг кластера

### Cluster Health

На странице `/admin/typesense/cluster` отображается:
- Общий статус кластера (healthy/warning/error)
- Список узлов с их статусами
- Метрики производительности

Включите "Auto-refresh" для автоматического обновления каждые 5 секунд.

## Аналитика

### Query Analytics

На странице `/admin/typesense/analytics` доступна аналитика:
- Топ поисковых запросов
- Количество запросов с результатами vs без результатов
- Средняя задержка поиска
- Популярные фильтры и фасеты

### No-Results Insights

Раздел показывает запросы без результатов, что помогает:
- Создавать синонимы для улучшения поиска
- Добавлять контент по популярным запросам
- Оптимизировать схему коллекции

## Безопасность и доступ

### Роли доступа

- **platform:admin** - Полный доступ ко всем функциям
- **tenant:owner** - Управление коллекциями и ключами своего тенанта
- **tenant:admin** - Только просмотр данных тенанта
- **tenant:editor** - Нет доступа к Typesense Admin

### Tenant Isolation

Все операции автоматически фильтруются по тенанту пользователя. Платформенные администраторы видят все данные.

## Лучшие практики

1. **Резервное копирование:** Делайте бэкапы перед удалением коллекций
2. **Тестирование:** Используйте песочницу (`/admin/sandbox`) для тестирования изменений
3. **Мониторинг:** Регулярно проверяйте Cluster Health
4. **Синонимы:** Создавайте синонимы для запросов без результатов
5. **Overrides:** Используйте для A/B тестирования и курации результатов
6. **Aliases:** Всегда используйте алиасы для production коллекций для zero-downtime операций

## Troubleshooting

### Коллекция не отображается

- Проверьте, что коллекция существует в Typesense
- Убедитесь, что у вас есть права доступа к тенанту
- Обновите страницу

### Ошибка при сохранении документа

- Проверьте, что все обязательные поля заполнены
- Убедитесь, что JSON валиден
- Проверьте схему коллекции на соответствие типов данных

### Синонимы не работают

- Проверьте, что синонимы применены к правильной коллекции
- Убедитесь, что локаль совпадает с языком запроса
- Используйте тестер для проверки

### Override не применяется

- Проверьте правило сопоставления (exact/contains/wildcard)
- Убедитесь, что query или filter_by указаны
- Проверьте, что документы в includes/excludes существуют
