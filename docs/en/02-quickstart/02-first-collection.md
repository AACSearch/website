## Что такое коллекция?

**Коллекция** — это набор документов с единой схемой. Аналогия:
- В SQL это таблица
- В MongoDB это коллекция
- В Elasticsearch это индекс

### Примеры коллекций

```
E-commerce сайт:
├── products     (товары)
├── categories   (категории)
├── reviews      (отзывы)
└── brands       (бренды)

Блог:
├── posts        (статьи)
├── authors      (авторы)
└── tags         (теги)

Документация:
├── articles     (статьи)
├── api_docs     (API документация)
└── tutorials    (туториалы)
```

### Что содержит коллекция?

```json
Коллекция: products
├── Схема (schema)
│   ├── title: string
│   ├── price: float
│   ├── category: string
│   └── in_stock: bool
│
├── Документы (documents)
│   ├── Document #1
│   ├── Document #2
│   └── Document #3
│
└── Настройки индексации
    ├── Какие поля искать
    ├── Какие поля фильтровать
    └── Параметры релевантности
```

## Типы полей

Платформа поддерживает множество типов полей для разных данных.

### 1. string (Строка)

Текстовые данные любой длины.

```json
{
  "name": "title",
  "type": "string",
  "optional": false,
  "index": true
}
```

**Примеры использования:**
- Названия (title, name)
- Описания (description, content)
- URL, email
- Теги, категории

**Опции:**
- `index: true` — использовать в поиске
- `facet: true` — использовать для фильтрации

### 2. int32 / int64 (Целое число)

Целые числа.

```json
{
  "name": "quantity",
  "type": "int32",
  "optional": false,
  "facet": true
}
```

**Примеры:**
- Количество (quantity, stock)
- Рейтинг (rating: 1-5)
- Год выпуска (year: 2025)
- Количество просмотров (views)

**Диапазоны:**
- `int32`: -2,147,483,648 до 2,147,483,647
- `int64`: -9,223,372,036,854,775,808 до 9,223,372,036,854,775,807

### 3. float (Число с плавающей точкой)

Числа с дробной частью.

```json
{
  "name": "price",
  "type": "float",
  "optional": false,
  "sort": true
}
```

**Примеры:**
- Цена (price: 99.99)
- Рейтинг (rating: 4.5)
- Вес (weight: 1.25)
- Расстояние (distance)

**Точность:** 7 десятичных знаков

### 4. bool (Булево)

Истина/ложь.

```json
{
  "name": "in_stock",
  "type": "bool",
  "optional": false,
  "facet": true
}
```

**Примеры:**
- Наличие на складе (in_stock)
- Опубликовано (published)
- Избранное (featured)
- Активно (active)

**Значения:** `true` или `false`

### 5. string[] (Массив строк)

Несколько текстовых значений.

```json
{
  "name": "tags",
  "type": "string[]",
  "optional": true,
  "facet": true
}
```

**Примеры:**
- Теги (tags: ["electronics", "gaming"])
- Категории (categories)
- Цвета (colors: ["red", "blue"])
- Авторы (authors)

**Фильтрация:** можно искать по любому элементу массива

### 6. int32[] / int64[] (Массив чисел)

```json
{
  "name": "related_ids",
  "type": "int32[]",
  "optional": true
}
```

**Примеры:**
- ID связанных товаров
- Годы (years: [2023, 2024, 2025])

### 7. geopoint (Геокоординаты)

Широта и долгота для геопоиска.

```json
{
  "name": "location",
  "type": "geopoint",
  "optional": true
}
```

**Формат:** `[latitude, longitude]`

**Пример документа:**
```json
{
  "name": "Starbucks",
  "location": [40.7128, -74.0060]
}
```

**Возможности:**
- Поиск в радиусе: "найти в пределах 5 км"
- Сортировка по расстоянию
- Фильтрация по области (polygon)

### 8. object (Вложенный объект)

Сложные структуры данных.

```json
{
  "name": "address",
  "type": "object",
  "optional": true
}
```

**Пример документа:**
```json
{
  "address": {
    "street": "Main St",
    "city": "New York",
    "zip": "10001"
  }
}
```

**Поиск:** по полям объекта: `address.city:New York`

### 9. object[] (Массив объектов)

```json
{
  "name": "variants",
  "type": "object[]",
  "optional": true
}
```

**Пример:**
```json
{
  "variants": [
    {"size": "M", "color": "red", "price": 29.99},
    {"size": "L", "color": "blue", "price": 31.99}
  ]
}
```

### 10. auto (Автоматическое определение)

```json
{
  "name": "metadata",
  "type": "auto",
  "optional": true
}
```

**Использование:** для динамических данных, когда тип неизвестен заранее.

### Сравнительная таблица

```
┌──────────────┬─────────────┬──────────────┬─────────────┐
│ Тип          │ Индексация  │ Сортировка   │ Фасет       │
├──────────────┼─────────────┼──────────────┼─────────────┤
│ string       │ ✓           │ ✓            │ ✓           │
│ int32/int64  │ ✓           │ ✓            │ ✓           │
│ float        │ ✓           │ ✓            │ ✓           │
│ bool         │ ✓           │ ✓            │ ✓           │
│ string[]     │ ✓           │ ✗            │ ✓           │
│ int32[]/64[] │ ✓           │ ✗            │ ✓           │
│ geopoint     │ ✓           │ ✓ (distance) │ ✗           │
│ object       │ ✓ (nested)  │ ✗            │ ✗           │
│ object[]     │ ✓ (nested)  │ ✗            │ ✗           │
└──────────────┴─────────────┴──────────────┴─────────────┘
```

## Настройка индексации

### Выбор поисковых полей

Не все поля должны участвовать в поиске.

**Индексировать:**
- ✅ Названия (title, name)
- ✅ Описания (description)
- ✅ Контент (content, body)
- ✅ Теги и категории

**Не индексировать:**
- ❌ ID и служебные поля
- ❌ Числовые данные (price, quantity)
- ❌ Даты (если не нужен поиск по дате)
- ❌ Технические метаданные

### Настройка веса полей

```json
{
  "default_sorting_field": "_text_match",
  "fields": [
    {
      "name": "title",
      "type": "string",
      "index": true,
      "infix": true
    },
    {
      "name": "description",
      "type": "string",
      "index": true
    },
    {
      "name": "tags",
      "type": "string[]",
      "index": true,
      "facet": true
    }
  ]
}
```

**При поиске:**
```json
{
  "q": "laptop",
  "query_by": "title,description,tags",
  "query_by_weights": "10,5,3"
}
```

Результат:
- Совпадение в `title` → max релевантность
- Совпадение в `description` → средняя
- Совпадение в `tags` → низкая

### Дополнительные опции

#### Token separators
```json
{
  "token_separators": ["-", "/"]
}
```

Пример: "wi-fi" будет разделено на "wi" и "fi"

#### Символы для удаления
```json
{
  "symbols_to_index": ["$", "#"]
}
```

Пример: "$100" будет проиндексировано с символом `$`

Для загрузки большого количества документов используйте bulk import.

```json
    "description": "Профессиональный ноутбук для бизнеса",
    "price": 899.99,
    "category": "Электроника",
    "in_stock": true,
    "tags": ["laptop", "business", "hp"]
  },
  {
    "id": "2",
    "title": "Клавиатура механическая",
    "description": "RGB подсветка, Cherry MX switches",
    "price": 129.99,
    "category": "Аксессуары",
    "in_stock": true,
    "tags": ["keyboard", "gaming", "rgb"]
  },
  {
    "id": "3",
    "title": "Мышь беспроводная Logitech",
    "description": "Эргономичная мышь с 6 кнопками",
    "price": 49.99,
    "category": "Аксессуары",
    "in_stock": false,
    "tags": ["mouse", "wireless", "logitech"]
  }

```

#### Формат JSONL (JSON Lines)

**Файл: products.jsonl**
```jsonl
{"id":"1","title":"Ноутбук HP ProBook 450","description":"Профессиональный ноутбук","price":899.99,"category":"Электроника"}
{"id":"2","title":"Клавиатура механическая","description":"RGB подсветка","price":129.99,"category":"Аксессуары"}
{"id":"3","title":"Мышь беспроводная","description":"Эргономичная мышь","price":49.99,"category":"Аксессуары"}
```

**Преимущество:** можно импортировать огромные файлы построчно

#### Формат CSV

**Файл: products.csv**
```csv
id,title,description,price,category,in_stock
1,"Ноутбук HP ProBook 450","Профессиональный ноутбук",899.99,Электроника,true
```

**Ограничения:**
- Сложно работать с массивами
- Не поддерживает вложенные объекты
- Нужно экранировать запятые и кавычки

### Импорт через API

```bash
curl -X POST \
  'https://api.aacsearch.com/v1/collections/products/documents/import' \
  -H 'X-API-Key: YOUR_API_KEY' \
  -H 'X-Tenant-ID: YOUR_TENANT_ID' \
  -H 'Content-Type: application/json' \
  --data-binary @products.json
```

**Для JSONL:**
```bash
curl -X POST \

  -H 'X-API-Key: YOUR_API_KEY' \
  -H 'X-Tenant-ID: YOUR_TENANT_ID' \
  -H 'Content-Type: application/x-ndjson' \
  --data-binary @products.jsonl
```

```json
      "line": 10,
      "error": "Missing required field: title",
      "document": {"id": "10", "price": 99.99}
    },
    {
      "line": 25,
      "error": "Invalid type for field 'price': expected float",
      "document": {"id": "25", "price": "invalid"}
    }
  ]
}
```

**Типичные ошибки:**
- Отсутствует обязательное поле
- Неправильный тип данных
- Дублирующийся ID
- Невалидный JSON

## Troubleshooting

### Ошибка "Field name already exists"

**Причина:** Поле с таким именем уже существует

**Решение:**
- Используйте другое имя
- Или удалите существующее поле (если коллекция пустая)

### Не удается импортировать CSV

**Проверьте:**
- Кодировка файла (должна быть UTF-8)
- Разделитель (запятая или точка с запятой)
- Экранирование кавычек

**Конвертируйте в JSON:**
```bash
# Используйте онлайн конвертер
# Или библиотеку (например, csvtojson)
```

### Медленный импорт

**Оптимизация:**
- Используйте JSONL вместо JSON
- Увеличьте batch size (до 500)
- Отключите сложные валидации
- Импортируйте в нерабочее время

### Документ не найден после импорта

**Возможные причины:**
1. Документ не проиндексировался (wait 1-2 секунды)
2. Ошибка в обязательных полях
3. Неправильная схема

**Проверка:**
```bash
curl -X GET \
  'https://api.aacsearch.com/v1/collections/products/documents/1' \
  -H 'X-API-Key: YOUR_API_KEY'
```

## FAQ

### Можно ли изменить схему после создания?

Да, но с ограничениями:
- ✅ Добавить новые поля
- ✅ Сделать поле опциональным
- ❌ Удалить поля с данными
- ❌ Изменить тип существующего поля

Для больших изменений:
1. Создайте новую коллекцию
2. Импортируйте данные с трансформацией
3. Переключите API на новую коллекцию
4. Удалите старую

### Сколько коллекций можно создать?

Зависит от плана:
- Free: 3 коллекции
- Starter: 10 коллекций
- Pro: 50 коллекций
- Enterprise: без ограничений

### Какой максимальный размер документа?

- Максимальный размер документа: 100 KB
- Максимальная длина строки: 64 KB
- Максимальный размер массива: 10,000 элементов

Для больших документов:
- Разбейте на несколько документов
- Храните большой контент отдельно (S3, CDN)
- Сохраняйте в коллекции только метаданные + URL

### Можно ли загружать изображения?

Нет, платформа не хранит файлы. Загрузите изображения на:
- CDN (Cloudflare, Cloudinary)
- S3, Google Cloud Storage
- Ваш сервер

Сохраняйте в коллекции только URL:
```json
{
  "title": "Product",
  "image_url": "https://cdn.example.com/product.jpg"
}
```
