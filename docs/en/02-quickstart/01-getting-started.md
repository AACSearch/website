## Регистрация аккаунта

### Шаг 1: Откройте форму регистрации

Перейдите на страницу регистрации: **https://app.aacsearch.com/register**

### Шаг 2: Заполните форму

Вам потребуется указать:

```
┌─────────────────────────────────────────┐
│     Регистрация в AACSearch             │
├─────────────────────────────────────────┤
│ Email:     [________________]           │
│ Имя:       [________________]           │
│ Фамилия:   [________________]           │
│ Пароль:    [________________]           │
│            (минимум 8 символов)         │
│ Повтор:    [________________]           │
│                                         │
│ [ ] Я согласен с условиями             │
│     использования и политикой           │
│     конфиденциальности                  │
│                                         │
│          [  Зарегистрироваться  ]       │
└─────────────────────────────────────────┘
```

**Требования к паролю:**
- Минимум 8 символов
- Минимум 1 заглавная буква
- Минимум 1 цифра
- Минимум 1 специальный символ

**Пример сильного пароля:** `MyP@ssw0rd2025!`

### Шаг 3: Подтверждение email

После регистрации на указанный email придет письмо с ссылкой подтверждения:

```
От: noreply@aacsearch.com
Тема: Подтвердите ваш email в AACSearch

Здравствуйте, John Doe!

Спасибо за регистрацию в AACSearch.
Пожалуйста, подтвердите ваш email, нажав на кнопку ниже:

[Подтвердить email]

Эта ссылка действительна в течение 24 часов.

Если вы не регистрировались на AACSearch, проигнорируйте это письмо.
```

**Важно:**
- Ссылка действительна 24 часа
- Без подтверждения email вы не сможете войти в систему
- Не нашли письмо? Проверьте папку "Спам"

### Шаг 4: Первый вход

После подтверждения email вернитесь на страницу входа:
**https://app.aacsearch.com/login**

Введите ваши учетные данные:
```

```

## Создание организации (Tenant)

После первого входа вы увидите мастер создания организации.

### Что такое Tenant?

**Tenant (организация)** — это изолированное пространство для ваших данных:
- Собственные коллекции документов
- Отдельные пользователи и роли
- Индивидуальные настройки поиска
- Изолированный биллинг
- Собственные API ключи

Одна учетная запись может управлять несколькими tenants (например, для разных проектов или клиентов).

### Шаг 1: Основная информация

```
┌─────────────────────────────────────────┐
│    Создание новой организации           │
├─────────────────────────────────────────┤
│ Название:                               │
│ [My Company                  ]          │
│                                         │
│ Slug (идентификатор):                   │
│ [my-company                  ]          │
│ https://my-company.aacsearch.com        │
│                                         │
│ Описание (опционально):                 │
│ [___________________________]           │
│                                         │
│            [ Далее ]                    │
└─────────────────────────────────────────┘
```

**Поля:**
- **Название** — отображаемое имя организации
- **Slug** — уникальный идентификатор (используется в URLs и API)
  - Только латинские буквы, цифры, дефис
  - От 3 до 63 символов
  - Пример: `my-company`, `acme-corp`, `project-2025`
- **Описание** — для чего используется организация (опционально)

### Шаг 2: Выбор региона

```
┌─────────────────────────────────────────┐
│    Где хранить данные?                  │
├─────────────────────────────────────────┤
│                                         │
│ ( ) 🇪🇺 Europe (Frankfurt)              │
│     - GDPR compliant                    │
│     - Latency: < 50ms (EU)              │
│     - Recommended for: Europe, Africa   │
│                                         │
│ (•) 🇺🇸 US East (Virginia)              │
│     - Low latency Americas              │
│     - Latency: < 50ms (Americas)        │
│     - Recommended for: US, Canada, LATAM│
│                                         │
│ ( ) 🇸🇬 Asia Pacific (Singapore)        │
│     - Coming soon                       │
│                                         │
│        [ Назад ]    [ Далее ]           │
└─────────────────────────────────────────┘
```

**Выбор региона важен:**
- Данные хранятся в выбранном регионе
- Влияет на latency для ваших пользователей
- **Нельзя изменить после создания** (требуется миграция)

**Рекомендации:**
- Европа / Россия / СНГ → **EU (Frankfurt)**
- США / Канада / LATAM → **US East**
- Азия / Океания → **Asia Pacific** (скоро)

## Управление ролями

Платформа поддерживает гранулярную систему ролей.

### Встроенные роли

#### 1. Admin (Администратор)
**Полный доступ ко всем функциям:**
```
✓ Управление организацией
✓ Управление пользователями
✓ Управление биллингом
✓ Создание/удаление коллекций
✓ Управление API ключами
✓ Настройка интеграций
✓ Просмотр аудит логов
✓ Все права Editor
```

**Когда использовать:** Владельцы организации, CTO, DevOps lead

#### 2. Editor (Редактор)
**Управление контентом:**
```
✓ Создание/редактирование коллекций
✓ Импорт/экспорт данных
✓ Настройка поиска
✓ Управление синонимами
✓ Настройка фасетов
✓ Просмотр аналитики
✗ Управление пользователями
✗ Управление биллингом
```

**Когда использовать:** Контент-менеджеры, маркетологи

#### 3. Viewer (Наблюдатель)
**Только чтение:**
```
✓ Просмотр коллекций
✓ Просмотр настроек поиска
✓ Просмотр аналитики
✗ Редактирование чего-либо
```

**Когда использовать:** Stakeholders, аналитики, отчетность

#### 4. Developer (Разработчик)
**Технический доступ:**
```
✓ Управление API ключами
✓ Просмотр документации API
✓ Тестирование endpoints
✓ Просмотр логов
✓ Настройка webhooks
✓ Все права Viewer
✗ Редактирование контента
```

**Когда использовать:** Backend разработчики, DevOps

#### 5. Analyst (Аналитик)
**Фокус на данных:**
```
✓ Полный доступ к аналитике
✓ Экспорт отчетов
✓ Настройка A/B тестов
✓ Просмотр метрик
✓ Все права Viewer
✗ Редактирование настроек
```

**Когда использовать:** Data analysts, product managers

## Получение API ключей

API ключи необходимы для интеграции платформы с вашими приложениями.

### Типы API ключей

#### 1. Search Only Key (Только поиск)
```
Права:
✓ Поисковые запросы (GET /search)
✓ Автодополнение (GET /suggest)
✓ Multi-search
✗ Запись данных
✗ Управление коллекциями

Безопасность: Можно использовать в frontend коде
```

#### 2. Admin Key (Администраторский)
```
Права:
✓ Все операции с коллекциями
✓ Создание/обновление/удаление документов
✓ Управление синонимами
✓ Настройка аналитики
✓ Все права Search Only Key

Безопасность: ТОЛЬКО для backend/server-side
```

#### 3. Scoped Key (Ограниченный)
```
Права: Настраиваемые
Примеры:
- Только определенные коллекции
- Только определенные операции
- Rate limiting
- IP whitelist

Безопасность: Для специфических use cases
```

## Troubleshooting

### Не пришло письмо подтверждения

**Решение:**
1. Проверьте папку "Спам"
2. Добавьте noreply@aacsearch.com в контакты
3. Запросите повторную отправку на странице логина

### Ошибка "Slug уже занят"

**Решение:**
- Slug должен быть уникальным в системе
- Попробуйте добавить суффикс: `my-company-2025`
- Или используйте domain: `mycompany-com`

### Карта не принимается

**Причины:**
- Недостаточно средств
- Карта не поддерживает международные платежи
- Требуется 3D Secure подтверждение

**Решение:**
- Проверьте баланс карты
- Свяжитесь с банком
- Используйте другую карту

### Ошибка при создании организации

**Проверьте:**
- Email подтвержден
- Все обязательные поля заполнены
- Slug соответствует требованиям (3-63 символа, латиница)

## FAQ

### Могу ли я создать несколько организаций?

Да! Один аккаунт может управлять несколькими tenants. Каждый tenant имеет:
- Собственный биллинг
- Отдельные лимиты
- Изолированные данные

Используйте для:
- Разных проектов
- Окружений (dev/staging/prod)
- Клиентов (если вы агентство)

### Можно ли изменить регион после создания?

Нет, регион нельзя изменить. Потребуется:
1. Создать новую организацию в нужном регионе
2. Экспортировать данные из старой
3. Импортировать в новую
4. Обновить API ключи в приложениях

### Как работает биллинг для нескольких организаций?

Каждая организация — отдельная подписка:
- Отдельные счета
- Отдельные лимиты
- Можно использовать разные карты

### Что происходит при превышении лимитов?

**Документы:**
- Загрузка новых документов заблокирована
- Существующие продолжают работать
- Поиск работает нормально

**Запросы:**
- HTTP 429 Too Many Requests
- Возобновляется в начале следующего дня

**Рекомендация:** Настройте alerts в разделе "Мониторинг"

### Могу ли я перенести данные из другой платформы?

Да! Доступны несколько способов:
- **Bulk Import API** — для CSV/JSON файлов
- **Готовые интеграции** — прямая синхронизация
- **Migration Service** (Enterprise) — мы сделаем миграцию
